# Digital MCP Server

A stdio MCP server for the [Digital](https://github.com/hneemann/Digital) logic
circuit simulator. It lets MCP clients create, inspect, validate, simulate, and
export `.dig` circuit files without manually operating the application window
or taking screenshots.

## Features

- Generate Digital `.dig` circuit files from structured designs.
- Inspect components, coordinates, attributes, and wires.
- Run embedded test cases through Digital's headless CLI.
- Export static circuit diagrams as SVG or high-resolution PNG images.
- Set `In` input or `Button` states and export images of the simulated circuit.
- Read Testcase data from `.dig` files and generate truth table images with
  PASS/FAIL results.
- Load circuits into Digital.app on macOS.

Simulation images are generated by creating a Digital model, applying input
states, and recalculating the circuit. They do not depend on GUI mouse clicks,
so states such as one active button or two active buttons can be reproduced.

## Installation and Usage

Run the server from the MCP repository root:

```bash
python3 digital_mcp_server.py
```

Example MCP client configuration:

```json
{
  "mcpServers": {
    "digital": {
      "command": "python3",
      "args": ["/absolute/path/digital-mcp-server/digital_mcp_server.py"],
      "env": {
        "DIGITAL_PROJECT_ROOT": "/absolute/path/Digital",
        "DIGITAL_JAR": "/absolute/path/Digital/source/target/Digital.jar",
        "DIGITAL_APP": "/absolute/path/Digital/modern/dist/Digital.app"
      }
    }
  }
}
```

Use these environment variables when the MCP server and Digital are in
separate directories:

```text
DIGITAL_PROJECT_ROOT       Digital project root; optional
DIGITAL_JAR                Path to Digital.jar; setting this explicitly is recommended
DIGITAL_JAVA               Path to a Java 21 executable; optional
DIGITAL_APP                Path to Digital.app for loading circuits
DIGITAL_SVG_CONVERTER      Path to an SVG-to-PNG converter; optional
DIGITAL_MCP_OUTPUT_DIR     Default directory for generated files; optional
```

PNG export requires one of `rsvg-convert`, `magick`, `convert`, or `inkscape`.
You can also specify the converter path with `DIGITAL_SVG_CONVERTER`.

## Main MCP Tools

### `digital_build_circuit`

Generate a `.dig` file from a `design` object. Optional arguments:

- `run_tests: true`: Run embedded tests.
- `render_svg: true`: Export an SVG alongside the circuit.
- `open: true`: Load the circuit into Digital on macOS.

Minimal design example:

```json
{
  "elements": [
    {"id": "a", "type": "In", "label": "A", "x": 100, "y": 100},
    {"id": "b", "type": "In", "label": "B", "x": 100, "y": 140},
    {"id": "g", "type": "And", "x": 200, "y": 100},
    {"id": "y", "type": "Out", "label": "Y", "x": 360, "y": 120}
  ],
  "wires": [
    {"from": "a", "to": "g", "input": 0},
    {"from": "b", "to": "g", "input": 1},
    {"from": "g", "to": "y"}
  ],
  "tests": [
    {"inputs": {"A": 0, "B": 0}, "outputs": {"Y": 0}},
    {"inputs": {"A": 0, "B": 1}, "outputs": {"Y": 0}},
    {"inputs": {"A": 1, "B": 0}, "outputs": {"Y": 0}},
    {"inputs": {"A": 1, "B": 1}, "outputs": {"Y": 1}}
  ]
}
```

Common supported components include `In`, `Out`, `And`, `Or`, `XOr`, `XNOr`,
`NAnd`, `NOr`, `Not`, `Clock`, `Const`, `Ground`, `VDD`, and `Testcase`.
Call `digital_design_schema` for the complete example and common pin conventions.

Element coordinates must be integers divisible by 20. Digital snaps components
to this grid when copying or editing them; off-grid positions can disconnect
their wires. Inverted gate outputs (`NAnd`, `NOr`, `XNOr`) are at `(x + 80, y + 20)`.

Circuit layout guidelines:

- Use horizontal and vertical wires with 90-degree bends.
- Enter gate inputs horizontally from the left. Put bends outside the gate,
  preferably 40 units before the pin, rather than along the gate's left edge.
- Keep branches separate and avoid duplicate or overlapping wire segments.
- Keep the layout readable without forcing every gate into rigid rows.
- Preserve connectivity and logic when rearranging a circuit. Check pin
  endpoints after an editor copy, and test actual behavior rather than only
  using don't-care (`X`) expected outputs. Inspect the exported SVG as well.
- Preserve unsaved editor changes by writing repairs to a clearly named copy.

### `digital_inspect_circuit` and `digital_run_tests`

```json
{"path": "/absolute/path/example.dig"}
```

`digital_inspect_circuit` returns component and wire information.
`digital_run_tests` invokes Digital's simulator and returns `passed`, the exit
code, and command output.

### `digital_export_rendered_image`

Export a static circuit diagram:

```json
{
  "path": "/absolute/path/motor_fault_indicator.dig",
  "format": "png",
  "output_path": "/absolute/path/motor_fault_indicator.png",
  "pixel_width": 4096
}
```

- `format`: `svg` or `png`; defaults to `png`.
- `pixel_width`: PNG width; defaults to 2048 and can be set to 4096 or higher.
- `output_path`: An absolute path is recommended. Relative paths must stay
  within the input file's directory.

SVG files are exported directly through Digital's CLI. PNG export first creates
an SVG, then renders it at the requested width using an SVG converter.

### `digital_export_simulation_image`

Apply input or button states and export a simulation image:

```json
{
  "path": "/absolute/path/motor_fault_indicator.dig",
  "inputs": {"A": 1, "B": 0},
  "format": "png",
  "pixel_width": 4096,
  "scale": 30
}
```

Input values can be numbers, booleans, or strings. `In` components are matched
by signal name, while `Button` components are matched by button label.
For the motor fault indicator example:

- `A=1,B=0`: One motor is running; the yellow indicator should be on.
- `A=1,B=1`: Both motors are running; the green indicator should be on.
- `A=0,B=0`: Both motors have failed; the red indicator should be on.

You can also pass `inputs` as a string, such as `"A=1,B=0"`. `scale` controls
the SVG's logical dimensions. `hide_test` hides the Testcase box by default.

### `digital_export_truth_table_image`

Read Testcase data from a `.dig` file, run Digital's tests, and generate a truth
table as SVG or PNG:

```json
{
  "path": "/absolute/path/motor_fault_indicator.dig",
  "format": "png",
  "output_path": "/absolute/path/motor_fault_indicator_truth_table.png",
  "pixel_width": 4096
}
```

The result includes `columns`, `rows`, and `validation`. The image title shows
`PASS` or `FAIL`. Circuits without embedded Testcase data return an error.

### `digital_load_circuit`

```json
{
  "path": "/absolute/path/motor_fault_indicator.dig",
  "app_path": "/absolute/path/Digital.app"
}
```

The server does not launch `Digital.app/Contents/MacOS/Digital` directly.
On macOS, starting that native launcher from Python can trigger `SIGABRT`
during Java/AWT registration. The tool uses a validated external Java runtime
and checks that the launched process remains alive. If the runtime is
unavailable, it returns an error without retrying the native launcher.
A successful result contains `loaded: true` and
`launcher: "managed-runtime"`.

## Generated Files

When running as a standalone repository, the server writes generated files to
its `generated/` directory by default. Set `DIGITAL_MCP_OUTPUT_DIR` to use a
different directory.

## Local Validation

Run the Python regression tests:

```bash
python3 -m unittest discover -v
```

Check Python syntax:

```bash
python3 -m py_compile digital_mcp_server.py
```

You can also run the underlying simulation snapshot CLI directly with a
Digital build that supports `CLI snapshot`:

```bash
java -Djava.awt.headless=true \
  -cp source/target/Digital.jar CLI snapshot \
  -dig /absolute/path/Digital/mcp/generated/motor_fault_indicator.dig \
  -svg /tmp/motor_fault_indicator_A1_B0.svg \
  -inputs A=1,B=0 -scale 30
```
